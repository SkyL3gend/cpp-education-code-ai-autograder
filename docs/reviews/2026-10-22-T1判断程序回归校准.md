# T1 判断程序的独立回归校准

本次新增 `planning/target_calibration.py`。它验证已生成的判断程序是否能区分任务作者的正确实现与已知缺陷实现，和“学生提交本身是否通过测试”“执行环境是否通过隔离门禁”分别记录。

## 当前验证范围

- 仅支持 `t1_phone_validation@1.0.0`，单文件合并工程或原四模块工程。
- 工程必须匹配已发布脚手架；允许 `isValidPhone` 函数体变化。未知布局、额外文件、菜单驱动、生成观测器、非 UTF-8 等形态明确返回 `UNSUPPORTED`，不会静默套用参考实现。
- 在单独证据目录中读取任务包的 `correct` 与 `faulty` 业务夹具，用原 bundle 的同一 driver、observer、断言绑定、迁移矩阵和编译选项构建。学生提交的文件不被覆盖；实际测评仍执行真实学生实现。
- 每个夹具执行全部 4 个正式用例。正确夹具必须全匹配；缺陷夹具必须仅在 `c_non_digit_11` 呈现已知错误：返回创建成功、已有 id=7 联系人完整保留、非法候选按夹具实际逻辑加入。任意错误输出造成的 MISMATCH 不算识别了这个缺陷。
- 每个夹具另执行 3 个独立校准挑战：11 位但以 2 开头、空串、全角数字；均保留已有联系人。挑战不加入封存任务包，不计入学生正式用例结果。
- 原 4 个正式用例没有单独检验规则 R2 的错误首位，这是任务覆盖边界，不能用校准挑战掩盖正式用例缺口。

## 资格与环境

通过仅标记 `qualification=T1_REGRESSION_CALIBRATED`。它是限定形态的自动回归证据，不是权威签审：`verifier_validation_level=CHECKED`、`grade_eligible=false` 始终保留。不得据此改写为 `CALIBRATED` 或 `REVIEWED`。

`gate_attested`、`gate_missing` 单独记录执行后端能力；WASM 试验后端不因判断程序回归通过而自动获得正式评分资格。模块仅运行真实 WASM 后端上的可信夹具，不接受 mock 结果作为校准证据，不调用模型。

证据绑定任务包 hash、原始提交 snapshot hash、目标文本文件集合 hash、完整 bundle hash、driver/observer/迁移矩阵 hash、独立夹具 hash、编译参数、环境 digest、后端能力摘要和每个请求/观测的 hash。

`calibration_binding_matches` 可阻止输入或环境变化后的陈旧证据复用。记录 hash 是一致性校验，不是签名或授权边界；只应消费主程序自己刚生成的证据，不能接受用户上传一个校准 JSON 自授资格。

## 集成入口

```python
record = calibrate_target_verifier(
    task=state.task,
    bundle=state.bundle,
    target_files=state.files,
    source_snapshot_hash=state.manifest.snapshot_hash,
    backend=state.backend,
    work_dir=state.run_dir / "evidence" / "target_calibration",
    limits=state.task.document.limits,
    cancelled=lambda: (state.run_dir / "CANCEL").exists(),
    deadline=self.deadline,
)
```

调用点在适配层构建/试跑完成后、冻结实际测评计划前。使用当前运行的总预算和取消信号；校准目录必须全新，拒绝覆盖旧证据。不能通过另起一份无限预算延长测评。

取消或预算耗尽分别记录 `CANCELLED` / `BUDGET_EXCEEDED`；不支持或回归失败都不应直接判学生代码失败。已有学生测试证据、回归校准状态、隔离门禁三者应分别展示。

## 纯逻辑验证

11 项单元测试通过，覆盖正确/缺陷双夹具、同一驱动、已有联系人保留、任意 MISMATCH 不算已知缺陷、自身全 MATCH 不授校准、未知工程拒绝、原四模块工程、数据不改写、陈旧证据失效、取消/预算、模拟后端拒绝和证据覆盖拒绝。单元测试使用测试替身，仅验证机制；真实 WASM 实验应另存原始编译和执行证据。

## 当前学生目标的补充规则检查

独立夹具校准验证的是判断程序本身；它不能替代当前学生程序的额外规则测量。例如一个只漏掉首位检查的学生实现可能通过封存的 4 个正式用例。

为此另提供 `run_target_challenges(task=..., bundle=..., backend=..., executable=..., run_id=..., work_dir=..., limits=..., cancelled=..., deadline=...)`：实际运行当前已冻结的学生 WebAssembly 文件，用相同的 3 个额外输入检查错误首位、空串、全角数字和完整初始状态。它不重新编译、不调用模型、不修改学生文件或封存任务，也不混入 4 项正式用例计数。

结果字段 `challenge_results` 包含每项输入、宿主期望、真实观测、断言比较、协议、终止方式；`challenge_counts` 只统计这 3 项补充检查。只有正常完成且观察到断言 MISMATCH 才标记 `defect_detected`。缺观测、协议错误或超限均为 `NOT_COMPARED`，不能当作发现学生业务缺陷。`grade_eligible=false` 始终保留。

记录绑定 `run_id`、任务包 hash、bundle hash、环境摘要及实际可执行文件字节 hash。执行期间文件或环境变化会标记 `INVALIDATED`。展示历史结果时应与该运行保存的冻结计划、重放清单中的环境和可执行文件 hash 核对，避免将另一提交的补充记录混入本次。

这部分新增 7 个使用假后端的单元测试，含额外首位缺陷识别、协议故障不归责学生、原正式用例不变、取消/预算、可执行文件变更和原生 EXE 拒绝；模块合计 18 项测试通过。未据此声称完成真实 WASM 验证。
