# 生日提醒 WebAssembly 接入与验证记录

初稿日期：2026-10-22；更新日期：2026-10-24。任务：`t2_birthday_today@1.0.0`。

当前状态：T2 已复用 T1 的 WebAssembly 测评框架，正确单文件与缺陷多文件 ZIP 均从独立解压包完成真实 LLM 生成、隔离执行及结果输出。以下保留首轮失败历史，并区分已完成实测与后续验收范围。

## 复用范围

T1 和 T2 通过 `planning/pilot_tasks.py` 的固定版本 profile 声明正式用例、补充检查、断言、可信夹具错误签名及适用范围。执行流程与结果页共享这些元数据，避免在前端、执行器和历史结果中分别硬编码 T1 的四项计数。

共用链路为：Web 上传 `.cpp` 或 ZIP → 提交快照 → LLM 生成与独立审查测试驱动 → 源码引用及契约检查 → 原始单元编译与适配探针 → AppContainer 隔离编译为 WASI → 独立夹具回归 → 冻结计划 → 正式用例 → 当前学生程序的补充检查 → 确定性断言比较与网页、JSON、CSV 展示。没有学生原生 EXE 的宿主直跑回退。

T2 适配要求驱动调用上传程序的真实 `ContactBook::birthdayReminders`，使用输入中的日期与提醒窗口，观察 `names` 和 `contacts_after`。日期来自用例，不依赖运行当天的系统时间。模型负责建立测试方式，业务比较按题库断言完成。

可信样例位于 `examples/wasm_birthday/`。单文件版按 `validators.h`、`contactbook.h`、T2 变体 `validators.cpp`、基础工程 `contactbook.cpp` 合并，仅移除本地头文件包含与 `#pragma once`；没有 `main()`。ZIP 保留同源的 4 个平级模块文件，已进行路径、CRC 和原始字节一致性校验。它们不是返回预置答案的模拟程序。

固定工程校准只允许 `daysUntilBirthday` 的实现发生变化；其他模块或工程形态变化时，不把当前独立夹具校准结论推广到未知结构。

## 正式用例与预期差异

题库保留 6 项正式用例，未改变已发布任务包：

| 用例 | 检查重点 | 正确版预期 | 已知缺陷版预期 |
| --- | --- | --- | --- |
| `c_today_exact` | 当天生日、窗口 0 天 | 提醒张伟 | 漏掉张伟，`a_names` 不符 |
| `c_today_window` | 包含当天与未来第 7 天 | 提醒张伟、周八 | 仅提醒周八，`a_names` 不符 |
| `c_already_passed` | 昨天生日按下一次生日计算 | 本次窗口无提醒 | 符合 |
| `c_leap_day` | 闰年 2 月 29 日当天 | 提醒钱七 | 漏掉钱七，`a_names` 不符 |
| `c_window_edge` | 第 7 天生日超出 6 天窗口 | 无提醒 | 符合 |
| `c_negative_window` | 负数窗口 | 无提醒 | 符合 |

正确单文件实际得到 **6 MATCH**，缺陷 ZIP 实际得到 **3 MATCH、3 MISMATCH**，与规则推导一致。缺陷版只把判断条件从 `birth < today` 变为 `birth <= today`，将当天生日推到明年。

两种夹具的全部用例都要求 `a_contacts` 符合：提醒查询不得改变联系人姓名、电话、生日、原始编号或记录数量。`names` 与 `contacts_after` 都按多重集比较，顺序不限，重复姓名与重复记录的次数不能被去重。

## 三项补充规则检查

| 检查 | 输入边界与目的 |
| --- | --- |
| `challenge_year_boundary` | 12 月 31 日的短窗口，含今天与次年 1 月 1 日，排除窗口外和已过生日 |
| `challenge_leap_boundary` | 2024 年 2 月 28 日、窗口 1 天，包含今天与合法闰日，排除 3 月 1 日 |
| `challenge_duplicate_birthdays` | 多人同日生日及重复姓名，验证完整提醒名单、多重集重复次数、原始编号和通讯录状态保留 |

同一模型判断程序对独立正确版和已知缺陷版各执行 `6 + 3` 项，共 **18 次夹具执行**。正确夹具应全部符合；缺陷夹具需产生 profile 声明的精确漏名签名，并保留通讯录。超时、编译失败、任意不匹配均不能冒充“成功识别已知缺陷”。

夹具回归之后，使用当前学生程序的实际 WASM 再执行这 3 项补充检查。它们单独展示，不混入 6 项正式计数或 JSON/CSV 正式用例列表。补充证据记录在 `evidence/target_challenges/target_challenges.json`，夹具回归记录在 `plans/target_calibration.json`。

补充范围是合法日期的短窗口；不在本轮替非闰年 2 月 29 日制定新的提醒约定。有限回归也不能证明任意输入或任意工程都适配正确。
