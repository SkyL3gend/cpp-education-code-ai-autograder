当前状态：T3 已复用 T1/T2 的框架，正确单文件和缺陷四模块 ZIP 均从独立解压包完成全新真实 LLM 测评、隔离执行及结果输出；网页/导出、八个新旧运行展示和前两题新包兼容性回放均已核查。

## 共用框架与规则

三个明确任务版本共用固定 profile、上传快照、LLM 判断程序生成与独立审查、源码引用绑定、AppContainer 隔离编译、WASI 执行、独立正确/缺陷夹具回归、补充检查和确定性断言。只开放 `t1_phone_validation@1.0.0`、`t2_birthday_today@1.0.0`、`t3_date_validation@1.0.0`；未知任务和版本仍拒绝，不执行学生宿主 EXE。

T3 的目标是 `isValidDate`，实际测评需调用上传程序的 `ContactBook::addContact`，观察 `created` 与完整 `contacts_after`：年份必须为 1900—2100（含端点），月份为 1—12，日期需真实存在。2000 年可有 2 月 29 日，1900 年不可；非法输入必须新增失败，且原通讯录不变。

样例位于 `examples/wasm_date/`。单文件版按 `validators.h → contactbook.h → validators.cpp → contactbook.cpp` 合并，仅移除本地头文件包含与 `#pragma once`，没有 `main()`。ZIP 仅含这四个平级文件；除 T3 变体的 `validators.cpp` 外，其余来自基准工程。已校验 CRC、安全路径与源文件字节一致，不包含模型 Key、上传记录或二进制依赖。

### 首轮失败与共用构建修复

首轮 `run_20261024_011706_108c70` 为 `ADAPTATION_FAILED`，并非学生业务缺陷：单文件 `ContactBook` 类内的内联 `contacts()` 被驱动只声明而未保留定义，产生 undefined symbol；修复驱动直接包含原 `.cpp` 后，原有链接清单又可能重复编译同一实现。

共用框架现仅对驱动直接、无条件、字面量精确包含的已声明 `.cpp` 去重最终链接清单。每个原始编译单元仍逐个 `-c` 检查、保留原字节；原 `.cpp` 经驱动实际编译一次，不复制或猜测业务实现。条件、宏、嵌套、raw string 等歧义不作猜测，源码与构建门禁不降低。生成与审查提示增加准确的 `host_build_contract`，包括宿主 `json_lite.h` 与协议校验，避免误审宿主已经提供的能力。

修复后真实可信编译器集成验证了业务与内联调用、原始单元检查、冻结及无 LLM 重放。共享 helper 与三题校准相关 96 项单元、1 项真实集成分别通过；最终完整套件为 **414 passed、0 failed、1 warning，155.85 秒**，证据为本地 `data/t3-pilot/inline-final-all.log`。警告仍为 Starlette/httpx 弃用提示，不将分批测试数量相加。较早的 377 项检查属于这次内联修复前的代码，不作为最终验收批次。
