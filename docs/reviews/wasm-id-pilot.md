## 共用范围与本题规则

普通 Web 仍只提供 LLM 适配测评；执行、夹具校准、补充和历史展示共用任务 profile。只开放当前题库 T1—T5 各自明确的 `1.0.0` 版本，未知任务或版本仍拒绝。新增第五题不增加部署依赖、不更换 SDK/隔离策略，不回退学生宿主 EXE，不自动授予正式评分资格。

本题要求真实执行输入中的有序操作：先 seed 初始联系人，再按顺序调用 `removeById`、`addContact`，最后观察 `contacts()`。新增编号要大于当前所有联系人编号，不得占用仍在使用的编号，已有编号保持不变；连续新增需要递增且唯一，删除不存在编号不改变原记录。

作者正确实现从 1 开始扫描当前记录，常规正编号按**当前最大值加一**分配，空通讯录从 1 开始。它没有永久历史计数器：删除最高编号后按剩余最大值计算、清空后重新分配 1 均符合本任务，不能额外宣称“任何历史编号永不复用”。

`id_list` 使用 **EQUALS**，必须按实际存储顺序原值输出，不排序、不去重、不补造编号。同 ID 重复要原样暴露；`contacts_after` 使用完整 Contact 多重集，保留原 ID、姓名、电话、生日和重复记录次数。不以编号集合或新增 ID 替代整个列表，不从用例输入修复学生实际状态。

样例位于 `examples/wasm_id/`。T5 correct/faulty 覆盖 `contactbook.cpp`，`validators.cpp` 和两个头文件来自基础工程。透明合并顺序为 `validators.h → contactbook.h → validators.cpp → contactbook.cpp`，仅移除本地头文件包含和 `#pragma once`，没有 `main()`。ZIP 只有四个平级源码文件，来源字节、CRC 与安全路径已核对，不含 Key、上传记录或二进制依赖。
