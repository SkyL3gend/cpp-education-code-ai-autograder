# 使用手册

更新日期：2026-10-24。面向首次使用的学生、教师和助教。

当前推荐使用 **Windows x64 WebAssembly 便携试验包**：解压、启动、上传程序，在本机查看真实运行结果。普通使用流程只提供 LLM 模式；基准模式及模拟后端保留给开发测试。

当前框架限定 T1 手机号校验、T2 生日提醒、T3 日期校验、**T4 姓名检索（`t4_name_search@1.0.0`）**，均只开放明确的 `1.0.0` 版本。四题均已有独立解压包真实 LLM 测评记录；新版也已核查前三题回放兼容性。旧便携包需要更新才能出现新增题目。各题均处于试验阶段，结果供程序检查与教学复核使用，不能直接计入正式成绩。其他题目和任意工程形态尚未完成同等验收。

本轮先同步源码、示例和文档；便携 ZIP 已在本地构建验证，尚未随本次更新公开发布，第三方运行库的再分发条件仍需核对。已有本地便携包可按下文操作，只有源码时请看第 7 节。

## 1. 下载、解压与启动

1. 在项目 GitHub 的 Releases 中下载 `cpp-assessor-wasm-pilot.zip` 便携资产（有附件的版本）。`Code → Download ZIP` 下载的是源码，不是便携包。
2. 将 ZIP **完整解压**到自己有写入权限的目录，例如 `D:\CppAssessor`。不要直接在压缩包里运行，也不要放在需要管理员权限才能写入的系统目录。
3. 双击解压目录中的 `START.cmd`，保留启动的终端窗口。
4. 在浏览器打开 <http://127.0.0.1:8766/>；没有自动打开时手动输入地址。
5. 选择对应题目：“手机号校验”“生日提醒”“生日日期校验”或“姓名检索”。填写自己的模型 API Key，选择程序文件并提交。

便携包自带 Python、Web 依赖、Wasmtime 和裁剪后的编译工具，**无需另装 Python、编译器、Docker 或 WSL**；应用运行时不会自动下载这些工具。模型请求仍需要网络和使用者自己的有效 Key。

本次包约 **77.1 MiB 压缩、192.0 MiB 展开**，相对 T3 压缩增量约 25 KiB。请额外留出提交快照、编译中间文件及报告的空间。后续版本体积可能变化，精确大小以同次附件与构建清单为准。

服务只供当前电脑使用，WebAssembly 试验后端要求监听回环地址，不能直接改成公开上传服务。当前已在一台 Windows 家庭版 x64 机器独立解压验证，干净 Windows 镜像、其他架构及杀毒软件兼容性仍待验证。

### 端口被占用时

先确认是否已经启动过同一服务；已有启动终端时，可以直接访问原地址。需要换端口时，在解压目录打开 PowerShell，执行：

```powershell
.\cpp-assessor-wasm-pilot.exe web --backend wasm_pilot --allow-unattested-backend --port 8767
```

然后访问 <http://127.0.0.1:8767/>。命令中的试验放行参数不会关闭 AppContainer 隔离，也不会赋予正式评分资格。

## 2. 配置模型服务

默认服务地址为 `https://api.deepseek.com`，模型为 `deepseek-chat`。在题目页的 **API Key** 输入框填写自己的 Key 即可；这是密码输入框，提交后页面不会回显原始 Key。

模型生成和审查“如何测试这份程序”的判断程序，不直接给学生打分。相关源码内容会发送到配置的模型服务，请按课程或单位要求选择服务。模型服务可能按调用量收费。

### 可选：在当前终端配置

若不想每次在页面输入，可以设置环境变量，再从**同一个 PowerShell 窗口**启动：

```powershell
$env:ASSESSOR_LLM_API_KEY = "替换为自己的Key"
.\cpp-assessor-wasm-pilot.exe
```

使用其他兼容服务时，同时设置地址和模型名：

```powershell
$env:ASSESSOR_LLM_API_KEY = "替换为自己的Key"
$env:ASSESSOR_LLM_BASE_URL = "https://你的服务地址/v1"
$env:ASSESSOR_LLM_MODEL = "你的模型名"
.\cpp-assessor-wasm-pilot.exe
```

地址填到 API 根路径，程序会追加 `/chat/completions`；不要重复填写这个末尾路径。服务需支持本程序使用的 Chat Completions JSON 输出接口，不能保证所有兼容服务或模型都适配成功。

另可自行创建 `%USERPROFILE%\.cpp-assessor\llm.env`，内容为一行 `ASSESSOR_LLM_API_KEY=自己的Key`。该文件只读取 Key；地址和模型仍通过环境变量设置。Key 来源优先级为：**页面输入 → 环境变量 → 用户配置文件**。配置改变后重启服务。

页面输入的 Key 不会写入数据库或报告；调用日志记录模型、耗时、token 用量、内容长度及哈希，不保存完整提示词和 Key。自行创建的 `llm.env` 会保留 Key，不要上传 GitHub、打包分享或粘贴进问题截图。

## 3. 上传程序并完成一次测评

建议先用随包样例确认流程，再上传自己的作业。手机号样例在 `examples/wasm_phone/`（[说明](../examples/wasm_phone/README.md)）；生日提醒样例在 `examples/wasm_birthday/`（[说明](../examples/wasm_birthday/README.md)）；日期校验样例在 `examples/wasm_date/`（[说明](../examples/wasm_date/README.md)）；姓名检索样例在 `examples/wasm_search/`（[说明](../examples/wasm_search/README.md)）。

| 样例 | 内容与预期 |
| --- | --- |
| `phone_correct.cpp` / `phone_correct.zip` | 手机号校验符合 T1 规则；4 项必测、3 项补充检查均应符合 |
| `phone_faulty.cpp` / `phone_faulty.zip` | 故意只检查长度与首位；`1380013800a` 会被错误接受，预期 3 项必测符合、1 项不符 |
| `birthday_correct.cpp` / `birthday_correct.zip` | 当天生日返回 0；单文件已实测 6 项必测、3 项补充均符合；ZIP 为同源四模块形态 |
| `birthday_faulty.cpp` / `birthday_faulty.zip` | 故意把当天生日推到明年；ZIP 已实测 6 项必测中 3 项符合、3 项不符，补充中 1 项符合、2 项不符 |
| `date_correct.cpp` / `date_correct.zip` | 按年份范围与真实日历校验；单文件实测 6 项正式、8 项补充全部符合 |
| `date_faulty.cpp` / `date_faulty.zip` | 故意不限制年份、二月总允许 29 日；ZIP 实测正式 3 项符合、3 项不符，补充 6 项符合、2 项不符 |
| `search_correct.cpp` / `search_correct.zip` | 忽略 ASCII 大小写，返回全部子串匹配联系人；单文件实测正式 5 项、补充 8 项全部符合 |
| `search_faulty.cpp` / `search_faulty.zip` | 区分大小写、只返回第一项；ZIP 实测正式 3 项符合、2 项不符，补充 3 项符合、5 项不符 |

单文件样例合并了业务模块，**没有 `main()`**；模型会生成调用真实业务函数的测试驱动。ZIP 样例保留四个模块文件。两者都实际编译执行，不是预置答案的模拟演示。

1. 首页选择对应题目，阅读规则。手机号、生日提醒、日期校验、姓名检索应分别选择对应题目，不要混用不同题目的样例。
2. 填写 Key；若服务已配置 Key，可留空使用已有配置。
3. 选择一个 `.cpp` 或 `.zip` 文件。表单也接受 `.h`、`.hpp`，但只有头文件通常不足以组成可测试程序。单个上传文件上限为 **20 MiB**。
4. 多文件项目请将必要源码和头文件放入 ZIP，保留相对路径；不要上传本机 EXE、编译缓存、密钥或无关个人文件。ZIP 还会进行路径、数量和解压总大小检查，具体拒绝原因以页面为准。
5. 可选的“修改前快照”用于留档和人工复核，不是标准答案，不参与正确性判定；首次试用无需填写。
6. 提交后等待完成并自动跳转到结果页。服务按单工作队列串行运行，多个提交需要排队。

流程包含模型生成与审查、适配探针、隔离编译、判断程序回归检查以及用例执行，比单次编译更耗时。独立便携包的真实在线采样：T1 为 **93.89 秒**，T2 正确单文件为 **136.75 秒**，各含 5 次成功模型调用；T2 缺陷 ZIP 为 **79.62 秒**，含 2 次成功模型调用，实际发现业务差异。这些是单次实测，网络、模型响应、代码规模与适配重试都会影响时间。

T3 正确单文件为 **84.85 秒**，缺陷 ZIP 为 **81.86 秒**，各有 2 次成功 API 响应，分别通过 28 次夹具回归。完整耗时包含模型与本地编译执行，不把约 12 秒的模型请求时间当作整次测评耗时。

T4 正确单文件为 **69.45 秒**、2 次成功 API 响应；缺陷 ZIP 为 **81.81 秒**、3 次成功响应（含一次候选修正），两次均通过 26 次夹具回归。具体速度与调用数不能保证每次相同。

试验包已完成固定工程形态的手机号题验证，以及生日提醒、日期校验、姓名检索正确单文件与缺陷多文件 ZIP 的真实测评。自行改变结构可能出现“适配失败”或“不支持”，说明系统未能建立可靠测试方式，不能直接认定学生程序错误。Windows 专用 API、宿主文件操作或特殊控制台交互也可能无法在 WASI 环境编译或运行。

### 上传生日提醒程序

1. 使用支持 T2 的新版服务，进入“生日提醒”题目页。
2. 首次可选择 `examples/wasm_birthday/birthday_correct.cpp`；多文件方式选择 `birthday_correct.zip`。它们包含相同的业务实现，ZIP 中是 4 个平级模块。
3. 按上述流程填写 Key 并提交。系统应让测试驱动调用上传程序的真实 `ContactBook::birthdayReminders`，观察提醒姓名列表与完整通讯录。
4. 再上传 `birthday_faulty.cpp` 或 `birthday_faulty.zip` 检查缺陷识别：当天生日被推到明年，预期在当天生日、当天与未来窗口、闰日当天这 3 项正式用例出现差异。

T2 检查当天、未来窗口、已过生日、闰日、窗口外边界和负数窗口，并要求查询不修改通讯录。补充检查跨年窗口、闰年二月边界、同日生日与重复姓名。姓名按**多重集**比较：顺序不限，同名联系人应保留重复次数；`contacts_after` 应保留全部原始联系人及其编号，不能重新分配 ID。

正确单文件实际完成 6 项正式与 3 项补充均符合；缺陷 ZIP 实际为正式 3 项符合、3 项不符，跨年和闰年二月补充检查也发现漏掉当天生日，同日重复姓名补充符合。两次独立夹具回归均通过，正式 6 项中的通讯录保留断言也均符合。完整真实 LLM 运行记录和验收范围以[生日提醒验证记录](reviews/wasm-birthday-pilot.md)为准。

### 上传生日日期校验程序

1. 使用接入 T3 的新版服务，进入“生日日期校验”题目页。
2. 选择 `examples/wasm_date/date_correct.cpp` 或 `date_correct.zip`，按通用流程配置 Key 并提交。模型应生成调用真实 `ContactBook::addContact` 的驱动，观测是否新增及完整通讯录。
3. 再选择 `date_faulty.cpp` 或 `date_faulty.zip`。实测已检出错误接受 `1900-02-29`、`1899-05-10`、`2101-01-01`，正式计数为 3 项符合、3 项不符；两个版本都拒绝 `2023-04-31`。

年份允许 1900—2100（含端点），月份与日期必须真实存在。非法生日应新增失败，且原有联系人及编号保持不变；不能只看日期判断返回值，忽略新增操作实际写入的联系人。T3 的 8 项补充独立于正式 6 项展示，实际正确版八项全符合，缺陷版在 `2100-02-29`、`2023-02-29` 错误新增，其余六项符合。运行、模型用量与首轮失败修复详见[日期校验验证记录](reviews/wasm-date-pilot.md)。

### 上传姓名检索程序

1. 使用接入 T4 的新版服务，进入“姓名检索”题目页。
2. 选择 `examples/wasm_search/search_correct.cpp` 或 `search_correct.zip`，配置 Key 并提交。系统应让驱动调用真实 `ContactBook::searchByName`，读取完整 `matches` 和 `contacts_after`。
3. 再选择对应 faulty 文件，检查 `an` 漏掉 `Anna Liu`、`LIU` 错误返回空列表的差异。实测正式五项中三项符合、两项不符，五项通讯录保留断言都符合。

检索按姓名任意位置子串匹配，ASCII 字母忽略大小写，返回全部匹配，空关键字返回空列表。匹配结果须保留原 ID、姓名、电话、生日，不能只显示姓名或重新编号；原通讯录也不能被改成小写。八项补充覆盖中间子串、重复姓名、多条中文匹配、混合大小写、空通讯录/关键字、空格和标点字面匹配，独立于五项正式。已核查两次运行各十三份完整记录及通讯录原状态；缺陷版补充三项符合、五项不符，见[姓名检索验证记录](reviews/wasm-search-pilot.md)。

## 4. 如何阅读结果

优先看具体用例的**输入、预期状态、实际状态和差异**，再看总体状态。

| 结果区域 | 怎么读 |
| --- | --- |
| 判断程序可靠性检查 | 同一判断程序对独立正确版和已知缺陷版夹具回归；T1/T2/T3/T4 分别 14/18/28/26 次；通过只说明固定范围内得到预期，不等同人工签审 |
| 必测用例 | T1 为 4 项，T2/T3 为 6 项，T4 为 5 项；`MATCH` 表示符合，`MISMATCH` 表示不符，未比较表示尚无可靠业务结论 |
| 补充规则检查 | 数量按任务 profile：T1/T2 各 3 项，T3/T4 各 8 项。分别检查号码、提醒、日期、检索的边界与完整状态；独立展示，不改变正式计数 |
| 运行与评分信息 | 区分“是否执行完成”“观测是否符合”和“是否具备正式评分资格” |

例如，`1380013800a` 应拒绝新增联系人；若实际新增成功，页面会显示不匹配，可展开完整联系人状态。若 `23800138000` 被接受，补充检查会显示首位规则的差异，即使原 4 项均符合也能提示这个缺陷。

**`CHECKED`、`INCONCLUSIVE` 和 `grade_eligible=false` 不代表程序没有运行。** 当前判断程序保持 `CHECKED`，试验后端也尚未完成正式评分验收，因此总体可能显示“结论不确定”，同时仍有逐项比较和任务补充结果。它们可用于定位问题，不能直接作为正式成绩；全部符合也只表示通过当前检查范围。

若为 `ADAPTATION_FAILED`，先检查模型生成的测试方式；若为 `INFRA_ERROR`、取消或超时，先看执行错误。不要把无法观测、基础设施故障或判断程序不可靠当作学生的业务缺陷。

### 下载与保留报告

结果页顶部可下载 **JSON / CSV**。JSON 含执行状态、用例断言、计数、来源及证据引用；CSV 以用例为行，使用 UTF-8 BOM，便于在 Excel 中打开。

JSON/CSV 正式用例列表按题目保留：T1 为 **4 项**，T2/T3 为 **6 项**，T4 为 **5 项**，不会把任务补充检查混入其中。需要完整补充证据时，同时备份该运行目录的 `evidence/target_challenges/target_challenges.json`。判断程序回归记录在 `plans/target_calibration.json`。

本轮已实际核对 T4 正确单文件、缺陷 ZIP，并用新版服务核对十三个已完成新旧运行的结果页与导出：JSON 计数、CSV 的 4/5/6 项正式用例行数及运行标识与报告一致，补充结果单独展示。前三题均在新包无新模型回放通过，非同源 POST 返回 403。此前 T3 八运行核查保留为历史记录，不混称同一批次。

### 每题会增加哪些成本

**接入工作量**包含规则、输入 Schema、正确/缺陷夹具、任务 profile、补充与回归验证；复用框架不等于不用验证新题。本轮新增外部依赖 0、SDK 不变，不按题再附带一套编译环境，不承诺固定接入小时或开发价格。首轮 T4 代码包相对 T3 增加 22,759 字节压缩、38,619 字节展开，是最终实测文档加入前的阶段采样，最终包需同次另测。历史 T3 对 T2 的增量另见日期校验记录，不能混作本轮数据。

**每份程序的系统 API 用量**：T4 两次成功实测分别 2 / 3 次响应、40,439 / 60,474 tokens，合计 **5 次响应、100,913 tokens**。缺陷版已含一次 `BUNDLE_INVALID` 后自动候选修正，两次上传均完成，没有失败整次上传另计；也不能额外把这个重试再算一遍。历史 T3 接入失败的开销单列在日期校验记录，不能只按成功调用推算所有新题。开发助手用量独立，不等同系统 API 费用；金额取决于模型、输入/输出与缓存计价，未核算人民币固定价，缓存也不能保证下次命中。

**本地执行成本**：各题夹具回归、学生补充本身不新增模型请求，仍消耗本机编译/运行时间和证据存储。T3 是 28 次夹具加八项学生补充，T4 是 26 次夹具加八项学生补充；重放同样不请求模型，但会重新编译执行。本次 T4 完整活动 69.45 / 81.81 秒，API 请求合计分别 12.41 / 21.36 秒，不能只用 API 时间当完整测评时延，也不承诺所有程序和电脑相同。

顶部“运行记录”可回看本地历史结果，`run_id` 用于对应报告与证据。分享前留意其中包含的学生代码、输入输出及文件信息。

## 5. 停止、数据与备份

等待页可点击“取消”；系统在阶段边界和受控执行期间处理取消，模型请求可能需等当前请求返回。不要反复提交来代替取消。

结束使用时，在启动终端按 **Ctrl+C**，等待服务退出；`START.cmd` 若停在“请按任意键继续”，再按键关闭。**关闭浏览器页签不会停止服务。** 正常退出更便于完成清理；需要立即关闭时可结束自己的启动终端。

默认数据在**解压目录下的 `data/`**；源码运行时在仓库根目录下的 `data/`：

| 路径 | 内容 |
| --- | --- |
| `data/app.sqlite3` | 运行索引和状态；可能伴随 `-wal` / `-shm` 文件 |
| `data/runs/<run_id>/objective_report.json` | 单次客观报告 |
| `data/runs/<run_id>/events.jsonl` | 单次流程事件 |
| `data/runs/<run_id>/plans/` | 判断程序、冻结计划和回归记录 |
| `data/runs/<run_id>/evidence/` | 编译、用例和补充检查证据 |
| `data/runs/<run_id>/submissions/` | LLM 测评提交快照及可选修改前快照 |
| `data/web_uploads/` | 上传原件，当前不自动清理 |
| `data/logs/llm_calls.jsonl` | 模型调用元数据日志 |

可用环境变量 `ASSESSOR_HOME` 指定数据根目录；题库默认在 `task_library/`，可用 `ASSESSOR_TASK_LIBRARY` 指定。换数据目录后，旧记录不会自动迁移。

备份前先停止服务，再复制整个 `data/`，避免漏掉 SQLite 未合并数据及报告依赖的证据。不要只复制数据库后删除证据。删除前确认不再需要历史提交和报告；`data/` 不含原始题库，但包含学生材料。用户配置文件中的 Key 与 `data/` 分开保存，不应随运行记录分享。

## 6. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 浏览器无法访问 | 保留启动终端，检查错误并访问实际地址；端口占用按第 1 节处理。关闭浏览器不代表服务已停 |
| 仍显示“上传测评暂不可用” | 确认使用本版便携 EXE，以及默认 `START.cmd` 或含 `--backend wasm_pilot --allow-unattested-backend` 的命令；旧的默认 `local` 服务会拒绝普通上传 |
| HTTP 402 / 余额或额度不足 | 到模型服务商检查余额、额度和计费权限，或更换可用 Key；本次没有完成测评，不是学生结果 |
| HTTP 401 / 403 / Key 被拒绝 | 检查 Key、模型权限、地址和模型名；改配置后重启服务 |
| HTTP 429 / 模型限流 | 稍后再试并检查账户速率限制，不要连续重复提交 |
| 网络或证书错误 | 检查联网、服务地址及本机证书/代理配置，不要关闭 HTTPS 证书校验 |
| 编译失败 | 看页面错误及编译证据，修正语法、缺失头文件或 ZIP 路径；若是模型驱动不匹配，按适配故障处理，不能直接归因学生 |
| `system()`、`Windows.h` 或 Windows API 不可用 | 当前编译目标是 WASI；系统命令、启动外部进程和 Windows 专有接口不属于该环境。改用可移植业务逻辑，不能靠关闭隔离放行 |
| 无法建立 AppContainer / 隔离环境 | 系统拒绝继续，没有非隔离执行回退。保留错误，检查目录权限、解压完整性和系统策略；不要默认以管理员运行或宿主直跑绕过 |
| 死循环、内存或输出超限 | 运行时限制会终止受控执行，查看终止状态；资源超限不等于该输入已完成正确性比较 |
| “适配失败” / 判断程序回归未通过 | 测试方式或工程形态未能可靠适配；先用随包样例复查，再保存该次证据供维护者排查 |
| 总体“不确定”但逐项有结果 | 这是试验评分门禁；按第 4 节阅读实际比较，不能据此登记正式成绩 |
| 必测用例符合但补充检查不符 | 补充检查发现了原用例未覆盖的差异；展开预期与实际状态，修复后重测 |
| 服务意外关闭，记录显示中断 | 重启后查看历史；未完成的测评不会自动变成成功，必要时重提并保留原记录 |

当前隔离方式：原生编译工具强制在零能力 Windows AppContainer 中运行，学生 WASM 通过 Wasmtime 执行，仅连接标准输入输出，不开放宿主目录或网络能力。它改善了本机运行边界，但不构成生产安全认证，也不是公开接收任意不可信上传的完整服务。

## 7. 从 GitHub 源码运行或重建（维护者）

`git clone` / `Download ZIP` **不包含便携包内的二进制依赖**。源码方式需要 Python 3.11+，准备阶段需要下载 WASI 工具；首次使用建议选已经发布便携资产的版本。

在源码仓库根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev,wasm]"
.\.venv\Scripts\python.exe tools/prepare_wasi_pilot.py
.\.venv\Scripts\python.exe assessor.py web --backend wasm_pilot --allow-unattested-backend --port 8766
```

模型 Key 的设置与第 2 节相同。准备工具后，源码方式同样使用 AppContainer + WASI，无需 Docker/WSL。仅安装 Python 包不能替代工具准备。

命令行可提交一次 LLM 测评：

```powershell
.\.venv\Scripts\python.exe assessor.py run --task t1_phone_validation@1.0.0 --submission examples/wasm_phone/phone_correct.cpp --llm --backend wasm_pilot --allow-unattested-backend
```

生日提醒使用对应任务和样例：

```powershell
.\.venv\Scripts\python.exe assessor.py run --task t2_birthday_today@1.0.0 --submission examples/wasm_birthday/birthday_correct.cpp --llm --backend wasm_pilot --allow-unattested-backend
```

日期校验使用对应任务和样例：

```powershell
.\.venv\Scripts\python.exe assessor.py run --task t3_date_validation@1.0.0 --submission examples/wasm_date/date_correct.cpp --llm --backend wasm_pilot --allow-unattested-backend
```

姓名检索使用对应任务和样例：

```powershell
.\.venv\Scripts\python.exe assessor.py run --task t4_name_search@1.0.0 --submission examples/wasm_search/search_correct.cpp --llm --backend wasm_pilot --allow-unattested-backend
```

重建便携 ZIP：

```powershell
.\.venv\Scripts\python.exe -m pip install pyinstaller
.\.venv\Scripts\python.exe tools/build_wasm_portable.py
```

输出在 `dist/cpp-assessor-wasm-pilot.zip`。公开分发前仍需核对工具链及 app-local VC++ DLL 的再分发条件，并完成干净 Windows 环境验证；本机验证不等于跨机器验收。

详细运行记录、隔离范围与性能见[手机号](reviews/wasm-phone-pilot.md)、[生日提醒](reviews/wasm-birthday-pilot.md)、[日期校验](reviews/wasm-date-pilot.md)和[姓名检索](reviews/wasm-search-pilot.md)验证记录。记录区分真实在线调用与复用已保存判断程序的离线重放，便于复核。
