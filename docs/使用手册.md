# 使用手册

本手册面向三类使用者：**教师/助教**（运行测评、看报告）、**题库维护者**
（编写任务包、校准）、**开发者**（二次开发与排查问题）。

---

## 1. 安装与自检

### 1.1 安装

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
```

安装后可用两种等价入口：

```powershell
python assessor.py <命令>     # 不安装也能用（脚本会把 src 加入 sys.path）
assessor <命令>               # 安装后的控制台入口
```

依赖：运行时 `pydantic>=2.6`、`jsonschema>=4.20`、`fastapi>=0.110`、`uvicorn>=0.27`、
`jinja2>=3.1`、`python-multipart>=0.0.9`；开发另需 `pytest>=8` 与 `httpx>=0.27`。
编译器要求 `g++` 支持 C++17，且在 `PATH` 中可找到：

```powershell
g++ --version
```

### 1.2 自检

```powershell
python assessor.py task list
python assessor.py sandbox capabilities --backend local
python -m pytest
```

`task list` 应列出 5 道 `PUBLISHED` 任务；`sandbox capabilities` 会打印后端能力，
其中 `network_block` 与 `filesystem_isolation` 为 `false` 表示当前后端不能承载
正式评分（见 §5）。

### 1.3 数据目录

默认写入仓库根目录的 `data/`：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `ASSESSOR_HOME` | `<仓库根>/data` | 运行记录、提交快照、报告、数据库 |
| `ASSESSOR_TASK_LIBRARY` | `<仓库根>/task_library` | 题库、基准工程、测试驱动 |

删除 `data/` 不会损坏题库；它只包含运行数据。SQLite 使用 WAL 模式，
备份时请连同 `-wal`/`-shm` 文件一起复制，或先停止进程。

## 2. 运行一次测评

### 2.1 用参照版本（最常用）

```powershell
python assessor.py run --task t1_phone_validation@1.0.0 --variant correct --allow-unattested-backend
```

- `--variant correct`：使用任务包内 `variants/correct/` 的参考实现；
- `--variant faulty`：使用缺陷实现，用于确认题目能识别错误；
- 输出会打印运行目录、任务、执行状态、判定、用例/断言计数与失败断言；
- 报告在 `<run_dir>/objective_report.json`。

### 2.2 用学生提交

提交可以是**目录**、**单个源码文件**或 **zip**：

```powershell
python assessor.py run --task t1_phone_validation@1.0.0 --submission .\student_work --allow-unattested-backend
python assessor.py run --task t1_phone_validation@1.0.0 --submission .\validators.cpp --allow-unattested-backend
python assessor.py run --task t1_phone_validation@1.0.0 --submission .\student_work.zip --allow-unattested-backend
```

覆盖规则：

1. 按**相对路径**匹配基准工程中的同名文件；
2. 匹配不到时，若某个文件的基本名（basename）在基准工程中唯一，则覆盖该文件；
3. 其余源码/头文件作为新文件加入工程；
4. 提交中必须至少有一个 `.cpp/.h/.hpp` 文件，且至少匹配到一个基准源码文件，
   否则按“非法输入”拒绝（`INVALID_INPUT`），不会把无关提交当成空工程测评。

`--target-before <path>` 可同时导入学生修改前的工程快照，保存在
`data/submissions/<id>/` 并在运行清单中关联，供人工复核使用；它**不是标准答案**，
不参与判定。

### 2.3 执行后端

| 后端 | 说明 |
| --- | --- |
| `local`（默认） | Win32 Job Object：CPU 时间、内存、进程数、墙钟、进程树终止 |
| `mock` | 不执行任何代码；按用例期望合成观测，只用于验证状态机与报告链路 |

`mock` 的报告一定带 `execution_backend=mock` 与说明文字，**不得计入任何验收**。

### 2.4 草稿任务

未发布（`publication_status=DRAFT`）的任务默认拒绝运行；调试时加 `--allow-draft`，
报告仍会记录任务状态，正式使用必须 `task publish`。

## 3. 查看结果

### 3.1 控制台摘要

```powershell
python assessor.py status <run_id>
```

打印工作流状态、执行状态、判定结论、校验等级、后端、用例/断言计数与最近事件。
`--json` 输出机器可读结果。

### 3.2 报告字段

`objective_report.json` 的关键字段：

| 字段 | 含义 |
| --- | --- |
| `execution_status` | 执行层面结果：`COMPLETED`、`SUBMISSION_COMPILE_ERROR`、`INVALID_INPUT`、`BUDGET_EXCEEDED`、`INFRA_ERROR`、`CANCELLED` 等 |
| `assessment_status` | 判定：`PASS` / `FAIL` / `INCONCLUSIVE` / `NOT_ASSESSED` |
| `grade_eligible` | 是否具备正式评分资格；本机后端恒为 `false` |
| `grade_eligible_reasons` | 不具备资格的原因，如 `EXECUTION_BACKEND_NOT_ATTESTED` |
| `validation_level` | `UNVERIFIED` / `CHECKED` / `CALIBRATED` / `REVIEWED` |
| `coverage` | 必测用例、分区、断言的覆盖与缺口 |
| `case_results[]` | 每个用例的比较结果、终止状态、协议状态、失败断言、证据引用 |
| `counts` | 用例与断言的必测/已尝试/完成/一致/不一致/未比较计数 |
| `provenance` | 任务版本、任务包哈希、提交 ID、工具链、后端、起止时间 |
| `observations_note` | 模拟后端或未过门禁时的额外说明 |

判定优先级（摘要）：

1. 取消 / 非法输入 / 不支持 → `NOT_ASSESSED`；
2. 归因学生侧的编译失败 → `FAIL`（不跑用例）；
3. 规则未发布、断言未确认、校验等级不足、覆盖不全、适配器/基础设施故障、
   必需断言未比较 → `INCONCLUSIVE`；
4. 任一必需断言不一致，或合规调用中学生程序崩溃/超限 → `FAIL`；
5. 全部一致 → `PASS`（只表示“通过当前测试集”）。

**“PASS”不等于“完全正确”**：它只说明通过了当前用例与断言集合。

### 3.3 导出

```powershell
python assessor.py report <run_id> --format json --out .\reports\<run_id>.json
python assessor.py report <run_id> --format csv
```

CSV 每个用例一行，列为：run_id、task_id、task_version、mode、execution_status、
assessment_status、grade_eligible、validation_level、case_id、purpose、comparison、
termination、protocol_status、failed_assertions、note。文件使用 UTF-8 BOM，
Excel 可直接打开；以 `= + - @` 开头的单元格会被加 `'` 前缀，防止公式注入。

### 3.4 复现判定

```powershell
python assessor.py replay <run_id>
```

只读取 `evidence/cases/<case>/observation.json` 与原始 stdout/stderr，用同一断言引擎
重新计算，并与报告中的断言结果逐条比较。一致时打印
“一致：N 个用例、M 条断言可由证据复现”；不一致返回退出码 3。
该命令**不会重新执行学生程序**。

### 3.5 取消

```powershell
python assessor.py cancel <run_id>
```

在运行目录写入 `CANCEL` 文件；运行器在阶段边界与用例之间检查，取消后报告为
`CANCELLED` / `NOT_ASSESSED`。由于用例有墙钟上限，最坏情况要等当前用例结束。

## 4. 维护题库

### 4.1 任务包结构

```
task_library/tasks/<task_id>/<version>/
  task.json                  # 任务元数据、规则、引用、发布状态
  io_template.json           # 输入/输出 Schema、操作、观测键、能力需求
  test_method.json           # 分区、断言、覆盖要求、已知缺陷矩阵
  cases.json                 # 用例（输入、期望、分区、断言、目的）
  reference_suite.json       # 参照版本（correct/faulty 及期望判定）
  reference_verifier/assertions.json   # 已验判断程序（与 test_method 断言一致）
  variants/correct/<file>    # 参考正确实现（只改必要文件）
  variants/faulty/<file>     # 已知缺陷实现（通常与基准工程一致）
```

所有引用用 `{id, version, sha256}` 描述，`sha256` 是**文件原始字节**的哈希；
任务包哈希覆盖 `task.json` 所在目录、基准工程目录与共享测试驱动目录。

### 4.2 用生成器生成

五道题由 `tools/build_task_packages.py` 生成，推荐以它为模板扩展：

```powershell
python tools\build_task_packages.py
```

脚本会：

1. 删除并重建 `task_library/tasks/<task_id>/<version>/`；
2. 写 `variants/correct/`（基于基准文件做**一次精确替换**）与 `variants/faulty/`；
3. 依次写断言定义 → IO 模板 → 测试方法 → 用例 → 参照版本 → 任务元数据，
   每步用刚写入文件的哈希填充引用；
4. 调用 `validate_task` 逐题校验并打印失败项。

新增题目时：

1. 在生成器里新增 `task_tN()`，定义规则、操作、断言、分区、用例与缺陷修复片段；
2. 若需要新的业务操作，先在 `task_library/shared/harness/test_entry.cpp` 增加
   `operation_id` 分支，并同步 `io_template.json` 的 `input_schema`/`output_schema`；
3. 保证至少一个 `kind="business_invalid"` 的输入分区被用例覆盖；
4. 运行生成器与 `tools\calibrate.py`，两者都通过才算可用。

### 4.3 校验与发布

```powershell
python assessor.py task validate task_library\tasks\t1_phone_validation\1.0.0
python assessor.py task publish  task_library\tasks\t1_phone_validation\1.0.0 --json
```

`validate` 会检查：必需文件、模型字段、Schema 版本与 `additionalProperties:false`、
禁止远程 `$ref`、用例 ID 一致、规则/分区/断言可追溯、覆盖要求满足、业务非法分区
存在、每个用例输入能通过输入 Schema、引用哈希一致、基准工程与测试驱动存在、
参照版本声明完整。任一失败都会列出检查项，不会“跳过继续”。

> 发布后请勿直接修改任务包内容；需要变更时提升 `version`，保留旧版本以复现历史报告。

### 4.4 校准

```powershell
python tools\calibrate.py                 # 全部任务、真实后端
python tools\calibrate.py --task t1_phone_validation
python tools\calibrate.py --backend mock  # 只验证链路，不代表真实编译
```

校准判定：正确实现必须 `PASS` 且无失败用例；缺陷实现必须得到声明的判定，且
`must_fail_cases` 全部出现在失败用例中。结果写入 `data/calibrations/` 与
SQLite 的 `calibrations` 表。

## 5. 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| `BACKEND_NOT_ATTESTED` / `UNSUPPORTED` | 当前后端缺网络或文件系统隔离。开发验证可加 `--allow-unattested-backend`；正式评分必须换通过门禁的后端 |
| `COMPILER_MISSING` | `g++` 不在 `PATH`；安装 MinGW-w64 并确认 `g++ --version` 可用 |
| `SUBMISSION_COMPILE_ERROR` | 学生代码编译失败；看 `evidence/compile/stderr.txt`，报告不执行用例 |
| `BACKEND_ERROR` / `INFRA_ERROR` | 后端或宿主异常；检查 Job Object 创建、工作目录权限与磁盘空间 |
| `INVALID_INPUT` | 提交为空、路径非法、压缩包超限、找不到可匹配源码；看错误消息 |
| 中文乱码 | 控制台可用 `chcp 65001`；管道输出已统一 UTF-8，CSV 使用 UTF-8 BOM |
| `replay` 不一致 | 证据被修改或断言引擎变更；不要手改 `evidence/`，用新版本任务重跑 |
| `task validate` 报哈希不一致 | 手工改了任务包文件；重新运行生成器，或按规范重算哈希 |

调试单个用例时，可直接查看：

```
data/runs/<run_id>/plans/requests/<case_id>.json      # 发给被测程序的内容（无期望值）
data/runs/<run_id>/evidence/cases/<case_id>/observation.json
data/runs/<run_id>/evidence/cases/<case_id>/stdout.txt
```

## 6. 常见问题

**Q：为什么 PASS 还显示“不计入正式成绩”？**
A：判定结论与评分资格是两件事。当前本地后端没有网络/文件系统隔离，按能力门禁
不能用于正式评分，但结论本身仍如实给出。

**Q：能不能直接在教师电脑上运行学生程序？**
A：不能。系统没有宿主直跑后备路径；后端能力不足时拒绝执行。这是实施方案 §9.3
的硬性要求。

**Q：学生程序死循环会怎样？**
A：达到 `case_wall_ms`（默认 3000ms）后终止整棵进程树，终止状态
`WALL_TIME_LIMIT`，归因学生侧，该用例“未比较”，整体判 `FAIL`
（`SUBJECT_CRASH_OR_LIMIT`）。

**Q：如何增加第 6—10 题？**
A：按 §4.2 的流程扩展生成器与测试驱动；第 3—4 周目标为 10 题、40 个用例，
并补充更多边界与“操作前后不变”的用例。

## 7. 使用本地 Web 界面

### 7.1 启动

```powershell
python assessor.py web                              # http://127.0.0.1:8765
python assessor.py web --port 9000 --no-open        # 指定端口、不自动开浏览器
python assessor.py web --allow-unattested-backend   # 允许本地 Job Object 后端真实运行
python assessor.py web --backend mock               # 演示模式：不编译、不执行代码
```

启动日志会打印监听地址与门禁提示。按 `Ctrl+C` 停止。Web 端与 CLI 共用
`data/`、`task_library/` 与同一套运行器，已有运行记录会直接出现在“最近运行”中。

### 7.2 页面与操作

1. **首页** 列出题库（任务 ID、版本、发布状态、用例数）和最近运行；顶部横幅显示
   当前后端是否为模拟后端、是否已通过能力门禁。
2. **任务页** 展示规则原文、操作、断言与用例清单（**不显示用例输入与预期值**，
   避免针对用例硬编码），并提供两个表单：
   - “用参照版本运行”：选择 `correct` / `faulty`，用于演示与校准复核；
   - “提交我的程序”：上传目录、单文件或 ZIP（≤20MiB，仅 `.zip/.cpp/.h/.hpp`），
     可另传“修改前快照”。
3. **等待页** 轮询 `/api/runs/<run_id>`；可点“取消”写入取消标记。运行结束后自动
   跳转到结果页。
4. **结果页** 显示结论徽章、执行状态、校验等级、后端、`grade_eligible`、用例与
   断言计数、判定理由（中文解释）、逐用例断言明细（expected/actual）、覆盖缺口与
   证据路径；顶部可下载 JSON / CSV。

### 7.3 直接调用接口

```powershell
# 查询状态
curl http://127.0.0.1:8765/api/runs/<run_id>

# 下载报告
curl -o report.json http://127.0.0.1:8765/runs/<run_id>/report.json
curl -o report.csv  http://127.0.0.1:8765/runs/<run_id>/report.csv
```

创建运行也可以脚本化：

```powershell
curl -X POST http://127.0.0.1:8765/runs `
  -F "task_ref=t1_phone_validation@1.0.0" `
  -F "variant=correct"
```

上传文件时把 `variant` 换成 `-F "submission=@我的工程.zip"`。

### 7.4 行为与边界

- 运行在进程内**单线程队列**中串行执行：一次只跑一个提交，后来的请求排队等待；
  页面会停留在等待页。
- 上传文件先落到 `data/web_uploads/<uuid>/`，再交给导入层做路径与大小校验；
  当前不会自动清理，可定期手动删除。
- Web 端**没有登录、鉴权与多用户隔离**，默认只监听 `127.0.0.1`；把 `--host`
  改成 `0.0.0.0` 会打印警告，请不要在不可信网络上这样做。
- Web 端只展示与导出报告，**不包含 AI 诊断**；诊断功能按实施方案在后续阶段接入，
  且不会改变客观判定与 `grade_eligible`。
- 端口被占用时换 `--port`；浏览器未自动打开时手动访问日志中的地址。
