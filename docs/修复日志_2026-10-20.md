## 1. 修复结果与边界

本轮优先修复了观测真实性、错误归因、适配验证，以及“参考基准判断程序的方法，再生成目标判断程序”的完整编排链。CLI 与 Web 使用同一套判定规则和数据库。

## 2. 四条核心链路的修改记录

### 2.1 观测真实性（F01）

发现：提取器会复制 initial_contacts，按姓名补全手机号、生日和编号，过滤记录或重新编号，导致未保存、存错数据也能 MATCH。

修改文件：`src/cpp_assessor/judge/extractors.py`。

| 函数/字段 | 修改 |
| --- | --- |
| `_records()` | 只解析实际行或详情块；保留真实字段、重复记录、重复姓名与原编号 |
| `_section()` | 按声明的 start/end 读取最后一段完整观测，禁止把多个操作的历史输出合成状态 |
| `_complete_records()` | 完整状态必须有边界、完整字段及可解析记录；空集合必须实际出现精确的 empty_marker，沉默不代表空 |
| `contactbook_menu_v1()` | created/rejected、saved_phone、contacts_after 仅由真实记录推出；有同名歧义不任意选一条 |
| `birthday_menu_v1()` | 提醒名单与动作后通讯录独立观测，初始数据不代替动作后证据 |
| `keyword_search_v1()` | 保留输出中的错误手机号；未证明结果完整时仅保留部分 observed_records，不伪造 matches |
| `contact_ids_v1()` | 不按 watch_names 过滤、加偏移或重编号 |

联动修改：`mode_two.py::_observer_params()` 不再自动把初始状态注入提取器；`planning/bundle.py::validate_bundle()` 拒绝 baseline_names、renumber_ids、id_offset 观测变换。`mode_two.py::_run_case()` 保留每项 NOT_COMPARED 原因，输出 Schema 不符不能被忽略。

验证：`tests/unit/test_extractors.py` 覆盖仅姓名行、实际错误手机号、原数据消失、重复姓名与记录、历史状态污染、空输出、假空标记、未知记录、编号偏移和独立提醒观测。旧测试中“从输入补 actual 才正确”的预期已改正。

### 2.2 错误归因与判定资格（F03、F07）

发现：模型生成的驱动编译不过会记成 SUBMISSION_COMPILE_ERROR；CHECKED 可给正式 PASS；崩溃分支还能绕过发布、规则确认和验证门禁。

修改文件和位置：

- `orchestrator/mode_two.py::_compile()`：先逐个编译原始单元，再构建生成驱动。原始单元仅编译成功不等于未知工程的构建契约已确认；错误不明仍为 BUILD_UNRESOLVED/UNKNOWN。
- `mode_two.py::_attribute_compile()`、`_compile_observer()`：区分生成物、基础设施和未知构建错误。编译证据的 `fault_owner` 是系统归因，`backend_fault_owner` 另存编译后端原始标签，避免二者混淆。
- `mode_two.py::_build_and_probe()`：生成物失败进入有界修正；环境不可用停止为 INFRA_ERROR；无法完成适配为 ADAPTATION_FAILED。禁止为让探针通过而换成合法输入或修改断言。
- `mode_two.py::_observe()`：未验证驱动的崩溃、异常、空输出不能归责学生，保留 UNKNOWN/ADAPTER。
- `judge/aggregate.py::aggregate()`：CALIBRATED/REVIEWED 才进入完整通过/失败聚合。CHECKED、覆盖缺口、断言未比较、适配故障均阻断资格；崩溃不再绕过这些门禁。
- `aggregate(..., original_build_confirmed=...)`：只有确认的原始源码编译错误才可能判学生 FAIL，不能只看编译器返回了非零。
- `tasks/calibration.py::calibration_level()`：验证当前包哈希、环境、真实参考版本报告、全用例和正反例结果。mock 不产生可信校准。
- `mode_two.py::execute()`：取消保留 CANCELLED 生命周期及 CLI 退出码 130，基础设施错误退出码 4，与标准运行器一致。

验证：`test_aggregate.py` 覆盖 CHECKED、未发布崩溃、未确认编译归因；`test_mode_two_llm.py` 用确实语法错误的生成 C++ 驱动验证“适配失败但不判学生错”，并检查编译日志归因；`test_repair_controls.py` 检查取消状态和退出码。

### 2.3 适配验证（F04）

发现：迁移矩阵只要列出分区名就通过，即使每项 status=gap；驱动不调用业务实现也可能通过。

修改文件：`src/cpp_assessor/planning/bundle.py`。

| 对象/函数 | 功能与约束 |
| --- | --- |
| `ReferenceLearning` | method_hash 必须匹配完整基准方法；必须列齐 setup_steps、action_steps、observations、assertion_ids、partition_ids |
| `SourceBinding` / `source_bindings` | ACTION/OUTPUT 必须引用存在的目标文件、实际符号与原文 source_quote；覆盖必需动作与观测 |
| `migration_matrix` | 不接受 coverage_gaps、gap 行、重复分区；每行有有效步骤、观测描述、全部必需断言及基准步骤 |
| `assertion_bindings` | 必需断言不可漏掉，不得改变 actual_observation_key |
| `validate_bundle()` | 检查脚本占位符、真实文件、路径和构建选项；函数驱动须出现映射业务符号的调用 |

运行时修改：`mode_two.py::_review_verifier()` 使用单独模型请求审查生成判断程序和源码对应关系，问题必须修正后再审；空 issues 不授予 REVIEWED。`_probe()` 使用独立 PROBE 标识，只验证驱动、协议和观测 Schema，不因学生业务返回不符合预期而修测试。探针与正式执行使用同一个 `_observe()`。

验证：`test_mode_two_bundle.py` 拒绝覆盖缺口、缺失绑定/基准学习记录、危险参数和错误占位符；`test_mode_two_llm.py` 验证完整链路。静态符号检查和模型审查无法证明任意 C++ 语义，因此即使通过全部试测，适配仍为 CHECKED。

### 2.4 LLM 参考基准测试方法的完整流程（F02）

发现：原提示主要给输入输出字段与可选提取器，缺少真实基准判断程序；新输出布局只能靠开发者补宿主正则。

新增：`src/cpp_assessor/planning/reference.py::reference_packet()`。修改：`orchestrator/mode_two.py::_prompt_payload()`、`planning/bundle.py::ObserverSpec`、仓库提示文件 `skills/cpp-microchange-judge-author/SKILL.md`。

| 步骤 | 系统输入、产物与失败处理 |
| --- | --- |
| 学习基准 | 提供完整 test_method、io_template、真实 test_entry.cpp 和辅助头文件，说明初始化、动作、观测、断言如何关联。文件超预算直接说明不支持，不能静默省略 |
| 查看目标 | 提供目标文件清单、源码及摘要；读取 target_before 快照，生成 target_before_diff。源码与注释仅作为数据 |
| 生成完整判断程序 | 输出 reference_learning、source_bindings、构建清单、stdin_script/function_driver、extractor/generated_observer、断言绑定和迁移矩阵 |
| 迁移测试方法 | 业务层级保持一致；“创建联系人”要实际创建，不能只测一个电话号码辅助函数；非法输入原样传入 |
| 生成独立观测器 | generated_observer 为 C++ 程序，读取 `{request, stdout, artifacts}`，从实际输出/声明文件生成完整协议与 actual。宿主仍执行固定断言，不把观测器当评分器 |
| 校验与独立审查 | 结构、路径、覆盖、原文引用和协议均检查；修复只能修改生成适配，不修改目标业务代码或判据 |
| 编译与试跑 | 分开留下原始单元、驱动和观测器编译证据；探针能得到合法观测后才冻结 |
| 冻结 | `_plan_hash()` 包含构建、bundle、任务哈希、源码快照、完整用例输入/期望、限额与环境；replay_manifest 保存 plans/generated/submissions 的逐文件字节哈希 |
| 执行与比较 | 每个正式用例前复核冻结哈希；原始 stdin/stdout/stderr、观测器输入输出和 observation.json 留证；宿主执行标准断言 |
| 报告与重放 | 报告区分系统执行状态、逐例比较、验证等级与评分资格；原冻结清单可重放，不再请求模型 |

`driver.startup_session`、`seed_session`、正式 session 按声明顺序执行；已删除自动挪动数字输入、删连续 0、填空占位符等猜测。seed 保留编号 0，缺字段直接报错。初始化仍必须来自用例声明，不能用模型臆造的数据替代。

验证夹具：`tests/target_verifier_fixture.py` 提供与基准接口不同的命名空间、嵌套头文件、备用 demo.cpp，以及宿主从未内置的 `ALIEN_LAYOUT:` 输出格式。集成测试分别通过真实 C++ 函数驱动与生成的独立 C++ 观测器跑完 4 个手机号用例，逐例 MATCH；汇总仍正确保持 INCONCLUSIVE、grade_eligible=false。

## 5. CLI 与 Web 对照复核

| 功能 | CLI | Web | 结果 |
| --- | --- | --- | --- |
| 校准后的标准参考版本 | run / status / report | 创建运行、API、历史、结果页和 JSON 下载 | 相同内核；正确 PASS、指定缺陷 FAIL；local 均不具备评分资格 |
| 未校准、mock、CHECKED | 原始状态与报告 | 原始状态与解释文案 | 不误显示正式通过；不以模拟 actual 当真实执行 |

| 观察型上传 | selfcheck --source | POST /reference | 任意上传不能在宿主自动执行；随附可信参考可用于开发自检 |
| 标准模式接口不符 | 返回清晰错误 | 结果页/API 显示同一错误 | 不再缩为单条探针后显示原题通过 |
| LLM 历史 | status / rejudge | /runs 和 /api/runs | 可查询同一 run_id、报告和等级，历史不再分库 |
| 排队/取消/异常收尾 | cancel 标记 | 提前建目录供排队取消 | reserved_run 只允许空目录或 CANCEL 文件，避免与拒绝覆盖保护冲突；孤立目录不永久显示等待 |

`interfaces/web/app.py` 修复排队预留目录冲突和无报告中断状态；`interfaces/web/i18n.py`、CLI 提示及 README 同步新的行为，去掉“演示开关可运行任意上传”等过时说法。版本号在 `config.py`、`pyproject.toml` 更新为 0.6.0。
