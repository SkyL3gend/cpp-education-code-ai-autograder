# 生日日期校验试测样例

- `date_correct.cpp` / `date_correct.zip`：年份限定为 1900—2100（含端点），按实际月份天数与闰年规则校验日期。
- `date_faulty.cpp` / `date_faulty.zip`：故意保留“二月总允许 29 日、没有年份范围限制”的缺陷，会错误接受 `1900-02-29`、`1899-05-10`、`2101-01-01`。

文件由仓库的 `contactbook_base@1.0.0` 与 T3 correct/faulty 变体组合而成，未改写业务实现。单文件版依次合并 `validators.h`、`contactbook.h`、`validators.cpp`、`contactbook.cpp`，仅移除本地头文件包含与 `#pragma once`；没有 `main()`。ZIP 版保留这 4 个平级模块的原始字节，路径与 CRC 已核对。

在支持 T3 的新版 `wasm_pilot` Web 服务中选择“生日日期校验”，上传任一 `.cpp` 或 `.zip`，由 LLM 生成调用真实 `ContactBook::addContact` 的测试驱动。非法日期应使新增返回 false，并保留原通讯录；不能只调用一个替代的日期判断函数或输出预置答案。在线生成需要可用的模型配置。

已用独立解压包完成全新真实 LLM 测评：正确单文件为 6 项正式、8 项补充全部符合；缺陷 ZIP 为正式 3 项符合、3 项不符，补充 6 项符合、2 项不符，两次均通过 28 次独立夹具回归。`2000-02-29` 与普通日期允许新增；缺陷版错误接受 `1900-02-29`、过低年份、过高年份，`2023-04-31` 在两个版本中都正确拒绝。补充另检出 `2100-02-29` 和 `2023-02-29` 被错误新增，不改变正式 6 项计数。

运行分别为 `run_20261024_013006_c77ff9`、`run_20261024_013221_b5666e`。结果仍为试测证据，`grade_eligible=false`，不能直接作为正式成绩。

其他题目的函数仍保留基础工程实现，这些文件仅用于 T3 验证。旧版只支持前两题的便携包需要更新。
